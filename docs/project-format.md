# Формат проекта PowerDriveSim 27

UTF-8 (BOM допустим), LF или CRLF, текстовые записи, десятичные числа SI с точностью double. Первая строка — `PowerDriveSim 27`. Комментарии начинаются с `#` в первой колонке. Строки в кавычках используют escaping `std::quoted`: `\"` и `\\`.

UUID состоят из 36 символов в нижнем регистре и уникальны в проекте. Имена и UUID однострочные. Геометрическое пересечение линий не задаёт электрическое соединение.

## Записи

Обязательные одиночные записи:

```text
project "uuid" "name"
profile stop_seconds step_seconds integration_method
nonlinear max_iterations voltage_absolute_tolerance current_absolute_tolerance relative_tolerance
wiring nets|wires
```

Записи объектов:

```text
node "uuid" "name" ground_boolean x y
component "uuid" "name" kind "positive_node_uuid" "negative_node_uuid" value initial x y closed_boolean
wire "uuid" "from_object" "from_port" "to_object" "to_port" bend_count x1 y1 ...
pattern "uuid" "name" x y initial_boolean
plot "uuid" "name" x y input_count time_begin time_end cursor_a cursor_b differential
code_block "uuid" "name" x y period phase "hex_encoded_C_source"
code_input "block_uuid" "port_uuid" "name" "unit" scalar_type initial
code_output "block_uuid" "port_uuid" "name" "unit" scalar_type initial
x-code-pin "block_uuid" "port_uuid" x y
x-code-icon "block_uuid" kind color filled "hex_encoded_text" point_count x1 y1 ...
x-object-icon "object_uuid" kind color filled "hex_encoded_text" point_count x1 y1 ...
scope_enabled boolean
event time_seconds "switch_or_pattern_uuid" closed_boolean
scope "channel_key"
scopeview time_begin time_end cursor_a cursor_b
```

В каталоге определения schema 21 публичный числовой параметр записывается как:

```text
public_parameter "uuid" "name" "unit" "object_uuid" "field" default "group" has_minimum minimum has_maximum maximum
```

Границы включительные; числовые поля minimum/maximum присутствуют всегда, но
учитываются только при соответствующем boolean `1`.

Writer всегда записывает `wiring`, `scopeview` и `scope_enabled`. `wiring` обязателен начиная с v4; при отсутствии необязательных настроек Scope используется выключенная запись и автоматический диапазон. `integration_method`: `BackwardEuler` или `Trapezoidal`. `kind`: `R`, `L`, `C`, `V`, `I`, `S`, `D`, `VP`, `IP`, `T`, `IGBT`. Boolean — `0` или `1`.

## Физические параметры

- `R`: value в Ohm; `L` в H; `C` в F; `V` в V; `I` в A.
- `S`: value зарезервирован; closed задаёт начальное состояние ключа.
- `D`: value=0, initial=0, closed=0; `p` — анод. Состояние определяется решателем.
- `T`: value=0, initial=0; closed задаёт начальный gate, `p` — анод. Запись
  `thyristor "uuid" holding_current initial_latched` задаёт конечный Ih≥0 и начальное
  удержание; значения по умолчанию 0/false. Только schema 11, только T, без дубликатов.
- `IGBT`: value=0, initial=0; closed — начальный gate. Атом канала без встроенного
  диода, ideal/PWL задаётся `semiconductor`. Требует schema 12.
- `VP`: ненагружающее измерение `u(p)-u(n)`.
- `IP`: идеальная ветвь нулевого напряжения, положительный ток направлен от `p` к `n`.
- initial задаёт uC в V или iL в A; для остальных компонентов поле зарезервировано.
- stop/step — положительные конечные числа. Интервал расчёта начинается с нуля.
- max_iterations: 1..1024. Абсолютные допуски положительные конечные, относительный — конечный неотрицательный. Допуски управляют проверкой complementarity и не добавляют проводимость.

События одного ключа в один момент времени не могут дублироваться, даже с одинаковым значением.

## Соединения

В режиме `nets` связность задаётся ссылками positive/negative компонентов на узлы. Wire/pattern-записи в этом режиме запрещены.

В режиме `wires` связность задаётся только концами проводов. Positive/negative у компонентов заполняет компилятор после разрешения сетей. Редактор записывает эти поля пустыми.

У электрического компонента есть `p` и `n`; у ключа также вход `gate`; у pattern — выход `out`. У VP/IP выход `out` относится к сигнальному домену, его нельзя соединять с electrical/gate. Блок `plot` принимает электрический потенциал (без нагрузки), scalar signal или gate на входы `in1`…`inN`, N=1..16. Каждый вход принимает один сигнал. График не изменяет электрическую топологию. У земли и узла порт называется `node`.

Schema 23 хранит модель пользовательского `code_block`: период и фаза заданы в
секундах, `scalar_type` равен `0` для `double` и `1` для `bool`, начальное
значение конечно, а для `bool` равно 0 или 1. UUID порта остаётся стабильным при
переименовании. Исходный многострочный UTF-8 C-код кодируется в hex без внешнего
файла. Запись `x-code-pin` хранит независимое положение порта на рамке блока.
Модель и формат сами по себе не включают блок в библиотеку: видимый редактор
появляется только после подключения flatten, runtime, snapshot и диагностики.

Schema 26 хранит векторную иконку блока кода в записях `x-code-icon`. `kind`
задаёт линию, прямоугольник, эллипс, ломаную или текст; `color` выбирает
семантический цвет текущей темы, координаты лежат в локальном поле 0…32.
Одна иконка содержит не более 64 примитивов, один примитив — не более 256 точек.

Schema 27 распространяет тот же редактор на компоненты, Gate, графики, теги и
экземпляры подсистем через `x-object-icon`. Запись является визуальным
переопределением конкретного объекта и не влияет на физическую модель. При
раскрытии экземпляра его собственная иконка исчезает вместе с рамкой, а иконки
сохранившихся внутренних атомов получают раскрытые UUID.

События pattern передаются подключённым ключам. Один gate принимает один драйвер. Прямые события ключа конфликтуют с подключённым pattern. Все ground-узлы объединяются в общую опорную сеть.

UUID именованного узла сохраняется для разрешённой сети (при объединении выбирается стабильный представитель). Для сети из одних выводов используется детерминированный application-defined UUIDv8. Точки проводов сохраняют геометрию, не меняя связность.

## Осциллограммы и расширения

Ключ аналогового канала — UUID узла или компонента. Ключ состояния ключа — `gate/UUID`. `scopeview` хранит диапазон времени и два курсора; `-1` у конца диапазона и курсоров означает auto/unset. Каждый plot хранит собственные диапазон и курсоры. В schema 20 флаг `differential=1` задаёт пары входов `pN`/`nN`; обычный график использует `inN`. Результаты расчёта и история undo/redo в проект не записываются. `scope_enabled=0` выключает сбор истории осциллограмм; графики записывают только подключённые сигналы независимо от этого флага.

Записи с префиксом `x-` сохраняются дословно как непрозрачные расширения. Историческое `x-scope` в старых примерах сохраняется, но не заменяет текущие `scope`-записи.

Неизвестные основные записи, лишние поля, неверные boolean и версии отклоняются. Новый физический смысл требует новой версии и миграционных тестов, а не скрытой семантики в `x-`.

## Миграции и сохранение

Loader читает версии 1–27, writer записывает только 27:

- v1→v2: добавляется BackwardEuler;
- v2→v3: добавляются стандартные nonlinear settings (64, 1e-9 V, 1e-12 A, 1e-9);
- v3→v4: добавляются режим nets, координаты узлов и настройки Scope по умолчанию;
- v4→v5: добавляется отключённая запись осциллограмм; блоки графиков отсутствуют по умолчанию.
- v6→v7: пустой каталог определений и экземпляров подсхем по умолчанию; контракт — [иерархия](hierarchy.md).
- v7→v8: источники V/I получают форму DC; остальные параметры формы не влияют на прежние схемы.
- v8→v9: S/D получают идеальную модель по умолчанию; Ron/Roff/Vf используются только при явном выборе PWL.
- v9→v10: динамика заряда диода выключена; прежние статические результаты сохраняются.
- v10→v11: добавлены T и явные параметры удержания; свойства существующих атомов не меняются.
- v11→v12: добавлен атом канала IGBT; прежние модели не меняются.
- v12→v13: добавлены режим начального состояния и предварительный прогон.
- v13→v14: добавлены параметры адаптивного шага.
- v14→v15: добавлены серии и сценарии расчёта.
- v15→v16: добавлены блокировка экземпляров, теги соединений и
  [gate-script](gate-scripts.md).
- v16→v17: добавлено параллельное сопротивление индуктивности.
- v17→v18: точки наблюдения Scope отделены от активной записи.
- v18→v19: добавлено оформление проводов.
- v19→v20: добавлен дифференциальный график.
- v20→v21: публичные параметры получили группу и включаемые границы диапазона.
- v21→v22: схема получила исходный код переменных и привязанные выражения
  числовых параметров; многострочный UTF-8-текст хранится без внешних файлов.
- v22→v23: добавлена невидимая до полной интеграции модель пользовательского
  «Блока кода» с типизированными портами, периодом, фазой и исходным C-кодом.
- v23→v24: Gate получил несколько программируемых выходов.
- v24→v25: добавлено независимое положение выводов многоканального Gate.
- v25→v26: добавлена векторная иконка пользовательского блока кода.
- v26→v27: векторные иконки стали доступны остальным объектам схемы.

Формат v1/v2 не содержит D/nonlinear, v1–v3 не содержит VP/IP/wires/pattern. UUID и расширения сохраняются при миграции. При открытии в редакторе режим nets преобразуется в явные провода; тест проверяет неизменность численного решения.

Writer использует classic locale и явно задаёт представление double/boolean. Редактор сохраняет через `QSaveFile` с атомарной заменой и отдельно записывает резервную копию.

CSV содержит metadata-комментарий, время, каналы с SI units и UUID, состояния ключей и все исходные отсчёты. Это экспорт, не snapshot/restart. Для воспроизведения сохраните `.pds`, CSV и версию ядра.

## Дополнения v6

`orientation "UUID" quarter_turns mirrored` сохраняет поворот 0–3 четверти оборота и горизонтальное отражение 0/1. Применяется к элементам, узлам, сигналам и графикам; отсутствие записи означает исходную ориентацию.

`pwm "UUID" "name" x y frequency duty delay` задаёт постоянный ШИМ: частота >0 Гц, заполнение 0..1, задержка ≥0 с. Все числа конечны. При нулевой задержке и ненулевом заполнении сигнал начинается с 1; заполнение 0 и 1 даёт постоянные уровни после задержки. Ручные события для этого же UUID запрещены. Старые v5-файлы получают исходную ориентацию и не содержат ШИМ.

## Дополнения v8

`source "component_UUID" kind offset frequency phase delay duty count t1 value1 ...`
задаёт форму существующего V/I. `kind`: 0=DC, 1=sine, 2=pulse, 3=piecewise-linear.
Фаза в rad, остальные значения SI. Повторный UUID, неизвестная цель и неправильный
порядок времён отвергаются. Семантика — [источники](sources.md).

## Дополнения v9

`semiconductor "component_UUID" model Ron Roff Vf` задаёт модель S/D: 0=ideal,
1=piecewise-linear. Числа в Ohm/Ohm/V. Запись сохраняет настройки, даже когда
выбрана идеальная модель; отсутствие записи означает исходные значения.
Неизвестная цель, повторный UUID и неверные параметры отвергаются. Семантика —
[ключи и диоды](semiconductors.md). Старые версии файла не принимают эту запись.

## Дополнения v10

`diode_charge "component_UUID" enabled transit_time carrier_lifetime initial_charge`
хранит режим динамики (0/1), времена в секундах и начальный заряд в кулонах.
Цель — D; повторы, неверные типы и параметры отвергаются. При ideal-модели
параметры сохраняются, но не используются. Контракт — [динамика заряда](diode-charge-model.md).

# Блок кода

«Блок кода» — первый пользовательский потребитель Signal IR после
приёмки M2. Пользователь задаёт список входов и выходов, их имена, тип
(`double`/`bool`), единицы SI, начальные значения и период выполнения, затем
пишет алгоритм на безопасном детерминированном подмножестве C.

Пример предполагаемого кода:

```c
static double integral = 0;
integral += error * dt;
command = kp * error + ki * integral;
gate = command > carrier;
```

Имена входов доступны только для чтения, выходы — для записи. `dt` и модельное
время предоставляются runtime явно. `static`-состояние сериализуется в snapshot.
Порты добавляются и переставляются в редакторе блока; связи используют UUID
порта, поэтому переименование не разрывает схему.
Для управления gate-входом тиристора выход блока задаётся как `bool`;
`double` относится к сигнальному домену. При несовместимом соединении
диагностика показывает тип и направление обоих выводов.
На схеме блок с одним выводом на каждой стороне имеет компактный корпус размером
с Gate. При нескольких выводах корпус расширяется, а полные имена, типы и единицы
портов доступны в подсказках при наведении.

Вкладка «Иконка» позволяет нарисовать собственное векторное обозначение линиями,
прямоугольниками, эллипсами, карандашом и текстом. Для примитивов выбираются
основной, signal, gate или акцентный цвет и заливка. Иконка хранится внутри `.pds`,
масштабируется без размытия и поворачивается вместе с блоком. Штатные шаблоны
имеют разные обозначения, но после вставки редактируются тем же редактором.
Редактор показывает создаваемый примитив во время удержания ЛКМ, поддерживает
настраиваемый шаг сетки и отключаемую привязку. То же действие доступно через
Inspector → «Редактировать иконку…» у остальных блоков схемы; очистка возвращает
штатное обозначение.

Окно настройки разделено на четыре вкладки: **Код**, **Входы**, **Выходы** и
**Иконка**. Его можно развернуть штатной кнопкой окна или кнопкой «Развернуть».
В редакторе работают поиск (`Ctrl+F`), поиск и замена (`Ctrl+H`), форматирование
(`Ctrl+Shift+F`) и встроенный справочник функций (`F1`). Общий набор функций
описан в [c-code-reference.md](c-code-reference.md).

## Импульсы для трёхфазного тиристорного регулятора

Создайте один «Блок кода» без входов с периодом `10e-6` с. На вкладке «Выходы»
создайте шесть выходов с именами `gAp`, `gAm`, `gBp`, `gBm`, `gCp`, `gCm`; тип каждого
— `bool`, начальное значение — `0`. Соедините их соответственно с управляющими
выводами тиристоров `A+`, `A−`, `B+`, `B−`, `C+`, `C−`. Вставьте во вкладку «Код»:

```c
double delay = ramp(0, 10, 0.008333333333, 0.001111111111);
gAp = phasepwm(50, 0.02, delay);
gAm = phasepwm(50, 0.02, delay + 0.010000000000);
gBp = phasepwm(50, 0.02, delay + 0.006666666667);
gBm = phasepwm(50, 0.02, delay + 0.016666666667);
gCp = phasepwm(50, 0.02, delay + 0.013333333333);
gCm = phasepwm(50, 0.02, delay + 0.023333333333);
```

При 50 Гц каждый импульс длится 0,4 мс. Задержка открытия уменьшается за 10 с
от 150° до 20°; отрицательная полуволна сдвинута на 10 мс, фазы B и C — на
6,667 и 13,333 мс относительно A. Это выходы именно «Блока кода» с именами
переменных; массив `IN[]` применяется в многоканальном Gate C. Блок вычисляется
на своих тактах, а gate-значения поступают в электрическую модель по причинному
правилу Signal IR. Разрешение фронта ограничено заданным периодом блока.
Проверка Reference CPU подключает все шесть выходов к библиотечному трёхфазному
AC-регулятору с синусоидальными источниками и резистивными нагрузками: каждая
полуволна проводит после своего импульса, сохранение и повторное открытие схемы
сохраняют связи. Это не является расчётом пользовательского `upp_balzam_test.pds`.
Готовая схема с этим блоком, тремя источниками, нагрузками и графиком напряжений —
`examples/ac-voltage-controller-3p-code.pds`. Для быстрого просмотра задано
0,04 с расчёта; чтобы увидеть изменение угла за все 10 с, увеличьте время расчёта.

## Безопасность и причинность

Блок не загружает произвольную DLL и не исполняет машинный код внутри GUI.
Эталонный путь компилирует проверенное подмножество C в ограниченный bytecode/IR:

- без указателей, рекурсии, файлов, сети, системных вызовов и wall clock;
- без динамического выделения памяти;
- циклы имеют статически проверяемую верхнюю границу;
- на один вызов действует бюджет инструкций и событий;
- деление на ноль, non-finite output, выход за границы и превышение бюджета дают
  адресную диагностику, а не завершают процесс;
- выходы формируются только из последнего принятого входного кадра. Значения
  электрического решения того же шага прочитать нельзя.

Reference CPU остаётся эталоном. Если позднее появится нативный/JIT backend, он
должен проходить differential tests с bytecode-путём и иметь безопасный fallback.

## Граница с Controller

Этот блок является универсальным signal-блоком для алгоритмов и формирования
выходных signal/gate-значений. Он не моделирует ADC, MCU timer/PWM, interrupts,
HAL или конкретный микроконтроллер. Эти сущности и выполнение полноценного
пользовательского C/C++ runtime остаются Milestone 6 и используют тот же
scheduler, а не отдельный путь внутри инвертора или GUI.

## Отличие от Gate

`Gate` остаётся компактным источником коммутационных команд: точной таблицей
фронтов, постоянным PWM и совместимым со старыми проектами C-режимом без входов.
Он удобен, когда ключам нужна только заранее заданная временная последовательность.
«Блок кода» — общий вариант для новой логики: принимает signal/gate-входы,
выполняется с заданным периодом, хранит состояние и выдаёт несколько типизированных
выходов. Поэтому новые регуляторы, сравнения и зависимую от измерений логику следует
строить блоками кода; Gate не является вторым контроллером.

## Порядок реализации

1. Типизированные signal/gate ports, связи и проверка единиц/единственного драйвера.
2. Signal IR и детерминированный scheduler с принятым входным кадром — выполнено
   в Reference CPU, включая точные периодические границы и Gate-выходы.
3. Модель/формат/GUI блока — выполнено: блок доступен в категории управляющих
   сигналов, портовые типы и единицы доступны в подсказках выводов, редактор
   изменяет расписание, код и интерфейс блока.
4. Парсер и bytecode безопасного C-подмножества, состояние и лимиты исполнения —
   выполнено общим C-интерпретатором.
5. Snapshot/continue, Undo/Redo, copy/group/flatten — выполнено; адресные ошибки
   удаления подключённых портов проходят через общую проверку проводов.
6. Тесты арифметики, PI/логики, gate edges, multirate, циклов, лимитов и аварий.

Тест Signal IR проверяет два блока с разными периодами и фазой, удержание
последнего принятого значения между тактами, адресную ошибку исполнения и
остановку бесконечного цикла по бюджету инструкций.

На текущем этапе модель документа включает блоки кода в копирование, вставку,
удаление вместе с проводами, поворот, выравнивание, группировку и раскрытие
подсхем. Эти операции сохраняют UUID портов внутри каждого блока и проходят
через общие транзакции Undo/Redo. Snapshot версии 4 сохраняет состояние
планировщика, `static`-переменные и входные кадры. GUI копирует и вырезает
одиночный блок; предпросмотр вставки учитывает его положение,
поворот и масштаб. Оконный тест проверяет Ctrl+C, Ctrl+V, Ctrl+X и Undo.
Оконный редактор сохраняет
UUID портов при переименовании и перестановке, отклоняет удаление подключённого
порта без изменения проекта и применяет принятые изменения одной Undo/Redo
транзакцией. Выходы блока записываются в подключённые Plot и выбранные каналы
Scope; сохранение и повторное открытие проекта проверены оконным тестом.

В категории «Управляющие сигналы» доступны шаблоны «Постоянный», «Ступень»,
«Нарастание» и «Синус». После вставки каждый из них остаётся обычным «Блоком кода»:
период, C-код и выход редактируются в том же окне. Шаблоны выполняются общим
Signal IR; оконная проверка сравнивает их значения до и после события и
сохранения проекта.

Там же доступны «Сумма», «Ограничитель», «Компаратор» и «И». У них есть только
показанные входы: два вещественных для суммы и компаратора, один вещественный
для ограничителя, два логических для «И»; все единицы SI пусты. Ограничитель
по умолчанию использует диапазон −1…1.

«Дискретный интегратор» и «Задержка 1 такт» также остаются обычными блоками
кода с одним вещественным входом `in` и выходом `out`. Оба выполняются каждые
100 мкс. Интегратор хранит накопленное значение в `static`; задержка выдаёт
сохранённый вход только на следующем такте. Поэтому оба читают только
предыдущий принятый входной кадр, а их состояние сохраняется в snapshot.

«Генератор несущей» формирует симметричный вещественный треугольник −1…1
частотой 1 кГц, а «ШИМ-компаратор» выдаёт `reference >= carrier`. Оба выполняются
каждые 100 мкс и остаются обычными редактируемыми блоками кода. У генератора нет
входов; у компаратора есть только вещественные входы `reference` и `carrier` и
логический выход `out`.

«Выборка и хранение» имеет вещественный вход `in` и логический вход `sample`.
При `sample = 1` блок запоминает принятый `in`, при `sample = 0` удерживает
последнее значение; выход и хранимое состояние начально равны нулю. Период по
умолчанию — 100 мкс. Входы читаются по общему правилу предыдущего принятого кадра.
Интеграционный тест проверяет удержание после короткого импульса `sample`,
сохранение `static`-значения в snapshot и побитовое продолжение расчёта.

Init-скрипт параметров уже реализован отдельно: «Расчёт → Переменные и
выражения…» задаёт константы, которые используются в числовых свойствах через
Inspector. Он вычисляется до flatten и не является runtime-блоком.

# Контракт задержанных сигналов и программного управления

Этот документ фиксирует контракт задержанных сигналов. Общий Signal IR,
причинный планировщик и пользовательский «Блок кода» уже работают в Reference
CPU; редактируемые шаблоны задержки на такт и выборки с хранением используют
тот же путь. Отдельный универсальный API задержанных сигналов и его оконная
приёмка ещё не завершены. Controller, ADC, MCU/HAL и запуск произвольного
нативного C/C++ остаются Milestone 6. `gate_script` выполняется безопасным
C-интерпретатором и видит только модельное время и собственное `static`-состояние.

## Причинность

Программный выход не имеет права читать неизвестные того же электрического
решения, на которое он влияет. Для момента `t[k]` допустимы только:

- константы и параметры, разрешённые до запуска;
- собственное явно сериализуемое дискретное состояние;
- последний **зафиксированный** кадр входных сигналов с временем не позже
  `t[k-1]`;
- результаты ADC/sample-and-hold, полученные в отдельном уже завершённом событии.

«Блок кода» читает только предыдущий принятый кадр, поэтому не может получить
«текущее напряжение» решения, на которое влияет его gate-выход. Если прямое
чтение в будущем API будет предложено, его требуется отклонять диагностикой
`instantaneous_signal_feedback`. Solver не добавляет скрытую задержку или
стабилизатор.

Детерминированный порядок одного timestamp:

1. применить ранее запланированные gate/event-события;
2. вычислить дискретные outputs, которым для этого момента достаточно прошлого
   зафиксированного кадра;
3. решить электрическую систему и обновить непрерывные состояния;
4. зафиксировать измерительные signal-выходы/ADC;
5. выполнить запланированные signal-задачи и Controller-задачи;
6. запланировать созданные ими gate edges только на причинно допустимый момент;
7. записать результат.

События одного timestamp имеют стабильный порядок по виду события и UUID, а
созданный на шаге 5 edge не может задним числом изменить уже решённый шаг 3.

## Доступные значения

Связи задаются UUID объекта и порта, а не отображаемым именем или положением на
холсте. Каждая привязка содержит:

- домен (`signal` или `gate`), scalar/vector shape и единицу SI;
- время кадра и признак valid/initial;
- числовое значение `float64` либо логическое gate-состояние;
- правило начального значения до первого зафиксированного кадра.

Прямой доступ к внутренним индексам MNA, адресам памяти backend или widgets
запрещён. Электрическая величина попадает в API только через явный probe/sensor;
физическое воздействие возвращается только через gate-порт либо controlled
source. Несовместимые единицы и удалённые UUID дают адресную диагностику до
начала исполнения.

## Слои реализации

Общий путь для «Блока кода» уже используется; будущие источники сигналов и
Controller должны проходить через те же слои:

`Visual signal graph → typed signal model → validation/schedule → Signal IR → backend execution`.

- Model хранит исходник, UUID-привязки, период/фазу задачи, начальные значения и
  версию языка.
- Compiler разрешает и типизирует зависимости, выявляет мгновенные циклы и
  формирует backend-независимый Signal IR.
- Reference CPU исполняет Signal IR и общий scheduler; GUI только редактирует и
  показывает диагностику.
- Нативный C/C++ и HAL не являются альтернативным коротким путём: в M6 они
  взаимодействуют с тем же scheduler через документированный Controller API.
- Инвертор принимает готовые gate edges и не содержит алгоритм PWM/управления.

Ограниченный язык выражений не получает файловый/сетевой ввод-вывод, wall clock,
случайность без явного seed, неограниченные циклы или несерилизуемую память.

## Snapshot и воспроизводимость

Snapshot будущего signal runtime обязан хранить:

- hash нормализованной программы и таблицы UUID-привязок;
- следующее время каждой задачи и стабильный event sequence;
- последний зафиксированный входной кадр с его временем;
- дискретное состояние программы и текущие outputs.

Изменение исходника, периода, единиц, привязок или версии языка делает snapshot
несовместимым до продолжения. При одинаковых IR/backend/precision порядок чтений
и gate edges повторяется бит-в-бит; backend с иной гарантией обязан явно указать
tolerance.

## Диагностика и отказоустойчивость

Ошибки содержат код, UUID блока/порта, путь экземпляров и модельное время:

- отсутствующая/несовместимая привязка;
- мгновенный цикл или чтение ещё не зафиксированного значения;
- неверная единица, форма или начальное значение;
- превышение бюджета инструкций/событий;
- нечисловой результат либо событие в прошлом;
- несовместимый snapshot/runtime.

Ошибка останавливает соответствующий запуск контролируемо и передаётся в общую
диагностику. Она не должна выходить исключением за границу UI-события, завершать
процесс или заменяться скрытым gate-состоянием.

## Последовательность реализации

1. Типизированные signal ports и независимый Signal IR без Controller/MCU —
   реализованы после приёмки M2.
2. Пользовательский [«Блок кода»](code-block.md) с редактируемыми входами/выходами
   и безопасным подмножеством C — реализован.
3. Причинный multirate scheduler, задержка на такт и выборка с хранением как
   шаблоны «Блока кода» — реализованы; отдельный явный API и его оконная приёмка
   остаются в работе.
4. Подключить ограниченные signal/gate expressions к этому IR, сохраняя старый
   open-loop режим и точные постоянные PWM edges.
5. Только в M6 добавить ADC, timer/PWM peripheral, Controller C/C++ runtime и HAL
   поверх того же scheduler.

До выполнения этих шагов `gate_script` не предоставляет значения схемы. Это
явное ограничение, а не молчаливая заглушка.

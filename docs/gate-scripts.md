# Программируемые gate-сигналы

Gate-блок в режиме «Код» хранит исходный текст в проекте и выполняет
детерминированную C-программу. Кнопка «Компилировать» в Inspector проверяет
текущий черновик тем же компилятором, который используется при запуске, не
изменяя проект.

В режиме «Таблица» фронты задаются парами «время — состояние». Пары можно
редактировать построчно либо вставить в таблицу через `Ctrl+V` сразу целиком:
поддерживаются два столбца, строки `время состояние` и массив вида
`{{0,0},{1e-3,1},{2e-3,0}}`. Время принимает те же SI-суффиксы, что и остальные
поля времени. Переключение «Таблица»/«Код» сохраняет введённые данные обоих
режимов; при компиляции используется только активный режим.

```c
const double base = 500;
double frequency = base * 2;
double duty = 1.0 / 4.0;
return pwm(frequency, duty, 100e-6);
```

Поддерживаются скалярные типы C, `const` и `static`, локальные переменные,
присваивания и составные присваивания, `++`/`--`, арифметические, логические и
битовые операции, тернарный оператор, блоки, `if/else`, `for`, `while`,
`do/while`, `break`, `continue`, `return` и пользовательские функции. Имена
регистрозависимы. `static` сохраняет состояние между последовательными
проверками Gate. Неизвестное имя или другая ошибка выдаёт
`invalid_gate_script` с UUID gate-блока.

Функции:

- `pwm(frequency, duty, delay)` (`square` — синоним): частота в Hz, заполнение
  от 0 до 1, задержка в секундах;
- `phasepwm(frequency, duty, delay)`: периодический сигнал с фазовой задержкой;
- `ramp(t0, t1, value0, value1)`: линейный переход между двумя значениями;
- `abs`/`fabs`, `min`/`max`, `sqrt`, `pow`, `sin`, `cos`, `tan`, `asin`,
  `acos`, `atan`, `atan2`, `exp`, `log`, `log10`, `floor`, `ceil`, `round`,
  `fmod`, `clamp`.

Переменные среды `stime` и совместимый с прежними проектами псевдоним `t`
содержат текущее модельное время в секундах при каждом вызове Gate-кода.
Значения узлов, токов и параметров схемы намеренно не доступны: поэтому скрипт
не образует неявную алгебраическую обратную связь с решателем.

## Несколько выходов

В свойствах Gate в режиме «Код» можно выбрать от 1 до 16 выходов. Для одного
выхода сохраняется совместимый синтаксис `return 0/1`. При двух и более выходах
код записывает состояния в проверяемый массив `IN`:

```c
for (int ind = 0; ind < 6; ++ind) {
    double phase = ind / 300.0;
    IN[ind] = phasepwm(50, 0.02, phase);
}
```

Каждый `IN[ind]` соответствует пронумерованному выводу блока. Индекс может быть
выражением или переменной цикла, но обязан быть целым и попадать в настроенный
диапазон. Ошибка индекса выдаёт `invalid_gate_script`; обращение за границы
памяти невозможно. Уменьшение числа выходов удаляет провода только исчезнувших
выводов и полностью отменяется через Undo.

Шесть каналов трёхфазного тиристорного регулятора в порядке `A+`, `A-`, `B+`,
`B-`, `C+`, `C-` можно сформировать одним блоком с шестью выходами:

```c
IN[0] = phasepwm(50, 0.02, ramp(0, 10, 0.008333333, 0.001111111));
IN[1] = phasepwm(50, 0.02, ramp(0, 10, 0.018333333, 0.011111111));
IN[2] = phasepwm(50, 0.02, ramp(0, 10, 0.015000000, 0.007777778));
IN[3] = phasepwm(50, 0.02, ramp(0, 10, 0.025000000, 0.017777778));
IN[4] = phasepwm(50, 0.02, ramp(0, 10, 0.021666667, 0.014444444));
IN[5] = phasepwm(50, 0.02, ramp(0, 10, 0.011666667, 0.004444444));
```

В режиме «Код» все программы имеют единую пошаговую семантику. Присваивания
`IN[n]`, вызовы `phasepwm`, циклы, ветвления и `static` не преобразуются скрыто
в таблицу событий: подготовленный байткод выполняется на каждом принятом шаге
интегрирования, а смена состояния относится к времени этого шага. Поэтому
форматирование исходника и промежуточные переменные не меняют способ выполнения.

Исходник разбирается, проверяется и компилируется в байткод один раз перед
расчётом. Проверяются доступные имена, права записи, размеры `IN[]`, переходы и
ограничения циклов; при выполнении сохраняются контроль диапазонов, конечность
результатов и бюджет инструкций. Повторного разбора текста на шагах нет.
Встроенный режим постоянного PWM остаётся отдельным явно выбранным режимом и
использует точные события; он не включается автоматически для Gate-кода.

Код не имеет ввода-вывода, доступа к ОС, указателей и динамической памяти.
Циклы и рекурсия защищены лимитом инструкций и глубины вызовов; превышение
лимита становится диагностикой, а не зависанием или падением приложения. При
одинаковом проекте и версии ядра последовательность событий воспроизводима.
Snapshot v3 хранит значения `static` и признаки их инициализации; изменение
исходного кода делает снимок несовместимым и требует нового запуска. Исходник
сохраняется в проекте однострочным безопасным кодированием. Загрузчик также
восстанавливает файлы schema 16–22, в которых форматирование раньше разрывало
одну запись Gate на несколько физических строк.

Отдельный [код инициализации и выражения параметров](parameter-expressions.md)
используют тот же детерминированный парсер и адресную диагностику. Переменные
параметров пока не экспортируются в `gate_script`; архитектурный
[контракт задержанных результатов](delayed-signal-api.md) зафиксирован, но сам
runtime остаётся следующим отдельным слоем.

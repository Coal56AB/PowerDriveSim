# Signal IR и причинный планировщик

Первый внутренний слой после M2 реализован независимо от GUI и подключён к
эталонному электрическому backend. Пользовательский редактор блока остаётся
отдельным проверяемым шагом.

`SignalIR` описывает периодические задачи, типизированные `double`/`bool` входы
и выходы, единицы SI, начальные значения и связи по UUID объекта и порта.
Reference runtime исполняет безопасный C-код с явными `t` и `dt`:

- входы доступны только для чтения, выходы — для записи;
- `static`-переменные сохраняются между вызовами;
- задачи одного времени исполняются в стабильном порядке UUID;
- все задачи одного времени читают один и тот же предыдущий принятый кадр;
- их результаты фиксируются совместно после завершения группы, поэтому порядок
  задач не создаёт мгновенную обратную связь;
- до первого valid-кадра используется начальное значение входного порта;
- probe и Gate формируют входной кадр только после принятого электрического
  решения, а периодические тики входят в общую сетку границ solver;
- логический выход блока через обычную типизированную Gate-связь управляет тем
  же generic stamp, что записанные события, PWM и Gate C;
- несовместимые типы/единицы, будущий или non-finite кадр, ошибка C-кода и
  превышение бюджета событий дают адресную `Diagnostic` со временем.

Schema 23 уже хранит невидимую модель пользовательского блока: стабильные UUID,
тип и единицы входов/выходов, начальные значения, период, фазу, расположение
портов и многострочный исходный C-код. Формат проверяет границы и выполняет
lossless round-trip; старые проекты 1–22 мигрируют с пустым списком блоков.

Иерархическое раскрытие сохраняет блоки, координаты, происхождение и публичные
порты каждого экземпляра. Отдельный `compile_signal_ir` разрешает проводные связи
каждого входа через UUID порта, включая публичные порты вложенных блоков и теги,
проверяет единственного драйвера, тип и единицы probe/Gate/выхода другого блока.
`bool` относится к gate-домену, `double` — к signal-домену. Общий Simulation IR
хранит backend-независимый Signal IR и явные привязки его UUID endpoint к
электрическим unknown/observation/Gate и целевым stamps. Reference CPU исполняет
задачи только на точных периодических границах; выход, вычисленный в момент `t`,
не меняет уже принятое решение этого момента и действует на следующий интервал.

Обычный запуск и snapshot/continue CodeBlock работают. Версия `.pdss` 4 сохраняет
следующий tick каждой задачи, `static`-состояние C, текущие outputs и последний
принятый входной кадр. Контракт снимка включает исходный код, период/фазу,
типы/единицы портов, UUID-привязки и целевые Gate-связи. Проверено побитовое
продолжение после Gate-фронта через следующий тик. До завершения оконного редактора
блок не показывается в библиотеке.

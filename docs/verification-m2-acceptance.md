# Проверка Milestone 2

Дата итогового аудита: 21 сентября 2026 года. Windows Release: полный набор
33/33 CTest, включая монолитный оконный прогон, прошёл за 109,38 s. Внутри
оконного набора пройдено 70 сценариев, 3 платформенно-зависимых измерительных
сценария пропущены штатно. Пять исходных критериев и добавленный пользователем
критерий полноценного C-кода инициализации/Gate подтверждены на Windows 10/11
x64. Этот документ фиксирует фактическое покрытие, а не заменяет тесты
утверждением о готовности.

## Критерии приёмки

1. **Раскрытие до атомов.** Converter-тесты раскрывают библиотечные экземпляры;
   адресный сценарий `editable_converter_examples` выбирает и редактирует каждый
   атом 2L/NPC, проверяет Undo и затем запускает изменённую generic-схему.
2. **Generic и fast path.** Все перечисленные преобразователи исполняются общим
   compiler/Reference CPU. Отдельных fast-path реализаций пока нет, поэтому
   эквивалентность двух путей не заявляется; такая проверка становится обязательной
   при добавлении первого fast path в M4.
3. **Энергия и установившиеся метрики.** Баланс источника, потерь и накопленной
   энергии проверяют `dcdc`, `bridges`, `dc-link`, `open-end`; средние/RMS и
   аналитические формы проверяют rectifier, controller и inverter-тесты.
4. **Аварийные режимы.** Тестируются shoot-through, конфликтующие идеальные
   источники, плавающие острова, current cutsets, невалидные параметры,
   несходимость/ошибки отдельных sweep-вариантов и несовместимые snapshots.
   Ошибки имеют код, UUID, путь и время там, где оно применимо.
5. **Запуск примеров.** Примеры доступны из меню как рабочие копии; core/CLI-тесты
   запускают их одной командой, оконные сценарии — штатной кнопкой Run.
6. **C-код Init/Gate.** Один core-runtime выполняет скалярный C с функциями,
   ветвлениями, циклами и состоянием. Статическая проверка видит ошибки во всех
   ветках, а бюджеты инструкций, вложенности и вызовов превращают опасный код в
   адресную диагностику. Кнопки «Компилировать» проверены в обоих редакторах.

## Исправления, найденные аудитом

- удаление разорванного скрытого current-probe больше не оставляет провод со
  ссылкой на удалённый объект; выводится предупреждение; обычное удаление
  наблюдаемых атомов и целых иерархических поддеревьев также очищает зависимые
  Scope-ссылки и цели серий в той же Undo-транзакции; публичные привязки
  защищены адресной диагностикой;
- необработанное C++-исключение в событии Qt перехватывается последней границей
  интерфейса и направляется в диагностику; неизвестные сбои фонового расчёта и
  серий также завершают операцию предупреждением с восстановлением UI, а не
  выходом исключения из future; разбор аргументов и ранняя инициализация CLI и
  desktop также находятся внутри верхней границы обработки, включая fallback
  для неизвестного исключения;
- числовые литералы и выражения теперь используют одинаковые inclusive/exclusive
  ограничения до изменения документа; `Ron = 0` не может попасть в модель через
  обход проверки выражением;
- восстановленный после навигации черновик таблицы снова помечается изменённым и
  может быть применён;
- dense-маркеры Scope имеют экранный бюджет вместо обхода миллионов отсчётов;
- точный индекс экстремумов сохраняет значения min/max внутри 64-точечных
  блоков и при построении читает каждый новый отсчёт один раз (36 ms для
  миллиона точек в offscreen Release-проверке);
- история результатов растёт стабильными блоками по 1024 отсчёта без
  перевыделения и перемещения полного префикса; random access, CSV и анализ
  остаются точными;
- подписи компонентов больше не перехватываются механизмом изменения размера и
  снова независимо перемещаются/поворачиваются мышью с полным Undo/Redo.
- UI-тестовые EXE по умолчанию запускаются через поставляемый рядом offscreen
  platform plugin даже вне CTest; прямой запуск больше не завершается диалогом
  инициализации Qt. Явный `-platform windows` сохранён для нативных/DPI-проверок.
- редактор серий показывает промежуточный прогресс и строки вариантов сразу во
  время работы, затем сверяет таблицу с итогом worker; ошибка открытия или
  завершения CSV-экспорта выдаёт предупреждение и не оставляет диалог
  заблокированным.
- прежний вычислитель выражений Init/Gate заменён общим C-runtime с `if/else`,
  `for`/`while`/`do`, функциями, присваиваниями, `static`-состоянием Gate,
  математикой и защитой от бесконечного/чрезмерно вложенного кода.

## Требования вне приёмки M2, которые остаются открытыми

- пользовательская цель длинной симуляции 10 s / 1e-7 быстрее 5 s пока не
  достигнута и относится к будущему ускоренному backend Milestone 4;
  вычислительная производительность Reference CPU и первоначальное построение
  точного индекса остаются предметом отдельной оптимизации. Штатный
  Reference CPU даёт около 2,09 млн шагов/s; даже небезопасный профиль без
  проверки невязки дал только 2,64 млн шагов/s и не был сохранён;
- критическое исправление переноса T-ответвления покрыто постоянным тестом, но по
  прямому требованию пользователя остаётся неподтверждённым до проверки на его
  исходной схеме;
- API задержанных сигналов и новый «Блок кода» ещё не реализованы; по плану это
  первый signal-layer после M2, до моделей машин, без переноса Controller/MCU из
  M6. Причинность и граница слоёв зафиксированы в `delayed-signal-api.md` и
  `code-block.md`.

Эти пункты нельзя отмечать выполненными, но они не отменяют подтверждённую
приёмку M2 и не должны смешиваться с её критериями.

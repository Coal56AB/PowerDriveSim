# Сохранение и продолжение состояния расчёта

Ядро Reference CPU поддерживает снимок на границе принятого шага и продолжение
с него. Состояние сохраняется независимо от записи каналов. Файл `.pdss`
содержит состояние расчёта; сама схема остаётся в `.pds`.

## CLI

```text
powerdrive-cli examples/diode-recovery.pds first.csv --steps 997 --snapshot-out state.pdss
powerdrive-cli examples/diode-recovery.pds rest.csv --snapshot-in state.pdss
```

`--steps` ограничивает число принятых шагов данного вызова, не меняя сетку
времени. Без него расчёт идёт до времени окончания проекта. `--snapshot-out`
сохраняет конечное состояние; `--snapshot-in` продолжает ранее сохранённое.
Первая точка продолжения повторяет последнюю точку предыдущей части.
При объединении CSV её нужно оставить один раз. Время остаётся абсолютным.

Можно увеличить время окончания проекта, переименовать или передвинуть
элементы, поменять отображение и набор записываемых каналов. Изменения
топологии, физических параметров, начальных условий, метода, шага и уже
прошедших gate-событий делают снимок несовместимым и диагностируются.
Будущие gate-события можно изменять. Табличная форма источника входит
в проверку совместимости целиком.

## Desktop

Меню **Расчёт** содержит сохранение и загрузку `.pdss`, **Продолжить из состояния**
и **Один шаг расчёта** (F10; сочетание меняется в настройках клавиш).
Две последние команды также доступны значками рядом с «Стоп».

Обычный «Пуск» начинает расчёт с исходных условий. После Stop или завершения
можно сохранить состояние. Загрузка проверяет соответствие текущей схеме,
методу и шагу, затем позволяет продолжить или выполнить один принятый шаг.
Один шаг без сохранённого состояния сначала выполняет инициализацию.
На времени окончания продолжение и шаг выключены; для продолжения увеличьте
время в верхнем поле. Во время работы эти команды выключены: сначала Stop.

Последовательные шаги и продолжение сохраняют историю графика, если набор
каналов остался тем же; граничная точка не дублируется. Загруженный файл не
содержит историю графика — запись начинается с времени снимка. Изменение
физики после снимка диагностируется ядром при попытке продолжения.
Новая или другая открытая схема сбрасывает текущее состояние.
Сохранение выполняется атомарно через QSaveFile.

## Контракт ядра

`SimulationSnapshot` находится в `core/ir`, не содержит Qt или дескрипторов
backend. В нём хранятся время, следующая точка глобальной сетки, состояния
и история C/L/динамических диодов, gate-состояния, активный набор диодов,
удержание тиристоров и алгебраические значения. Матрицы и факторизации
в снимок не входят; кеш создаётся лениво после продолжения.

`ExecutionOptions` задаёт исходный снимок, необходимость его сохранения
и необязательный предел принятых шагов. По умолчанию снимок не создаётся.
Обычный Run сохраняет прежние затраты памяти; снимок не требует истории
результатов. Stop возвращает снимок последнего принятого состояния,
включая инициализацию, если первый шаг ещё не выполнен.

Версия файла — 1. Числа записываются с `max_digits10` и независимой от
локали десятичной точкой. Проверяются версия, конечность чисел, размеры
массивов, сетка времени и согласованность состояния C/L с алгебраическими
значениями. Совместимость задаёт стабильный идентификатор нормализованного
IR и уже применённых gate-событий. Это идентификатор совместимости,
а не криптографическая подпись файла.

Продолжение не выполняет повторную инициализацию: она могла бы изменить
историю Trapezoidal или состояние тиристора. Пройденные события не применяются
повторно, глобальная сетка не начинается заново.

## Проверки

CTest `snapshots` разбивает RC, RLC, pulse RC, RL freewheel, восстановление
диода, тиристорный выпрямитель, AC-регулятор и двойной инвертор на части
по 137 шагов. После каждой части состояние записывается и читается из файла.
Все точки, gates и времена побитово совпадают с непрерывным запуском для
Backward Euler и Trapezoidal. Отдельно проверяются увеличение времени
окончания, Stop при инициализации, отсутствие записи, переименование,
несовместимая модель и повреждённый файл.

CLI-проверка `diode-recovery.pds` после 997 шагов сохраняет и загружает
состояние; объединённые 7203 точки CSV совпадают с непрерывным расчётом.

Оконный тест проверяет два шага, непрерывное продолжение, сохранение/загрузку,
совпадение всех точек RC, несовместимый шаг и перезапуск с нуля. Live-тест
проверяет продолжение одним шагом после Stop без потери истории.

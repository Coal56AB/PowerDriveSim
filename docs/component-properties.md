# Конфигурации свойств компонентов

Каждому типу соответствует JSON в `apps/desktop/components`. CMake включает конфигурации в Qt resources и копирует каталог `components` рядом с EXE. При запуске одноимённый внешний файл заменяет встроенный. Для проверки другого каталога используется `PDS_COMPONENT_DIR`; изменения вступают в силу после перезапуска.

`type` — существующий тип модели. Массив `fields` задаёт порядок и состав полей. `palette` задаёт действие вставки, перевод названия, категорию, короткое название и признаки `fixed`/`hidden`.

## Поле

| Ключ | Значение |
| --- | --- |
| `key` | Имя свойства в API модели |
| `editor` | `text`, `number`, `bool`, `integer`, `enum`, `events`, `points`, `samples` |
| `label` | Ключ RU/EN перевода либо буквальная подпись |
| `unit` | Единица для SI-разбора и отображения числа |
| `scale` | Множитель отображения; например, 100 для заполнения ШИМ в процентах |
| `min`, `max`, `exclusiveMin` | Границы вводимого значения в отображаемой шкале |
| `condition` | `internal_gate` скрывает локальное управление при внешнем gate-источнике |
| `when` | Объект `{"source_mode":[1,2]}` показывает поле для перечисленных значений enum-свойства |
| `options` | Для `enum`: массив объектов с числовым `value` и переводимым `label` |
| `span` | `true` размещает редактор на полной ширине панели; используется таблицей источника |
| `inline` | `name` или `value`: редактирование соответствующей подписи на схеме |
| `inlinePart` | Индекс части составной подписи, разделённой ` · `; используется для частоты/заполнения ШИМ |

Например, добавление поля координаты в `fields` резистора не требует правки Inspector:

```json
{"key":"x","editor":"number","label":"Положение X","min":-10000,"max":10000}
```

Общие свойства объектов: `name`, `x`, `y`. Компоненты предоставляют `value`, `initial`, `closed`; управляющие источники — `closed`, `events`, а PWM — `frequency`, `duty`, `delay`; график — `inputs`; провод — `bends`. V/I дополнительно предоставляют `source_mode`, `source_offset`, `source_frequency`, `source_phase`, `source_delay`, `source_duty`, `source_points`. В поставляемых конфигурациях выбраны поля, относящиеся к конкретному типу. Одинаковый ключ использует одинаковый тип редактора во всех конфигурациях. `events` редактируется таблицей «время / состояние», `points` — строками `x y`, `samples` — таблицей «время / значение» с единицами из конфигурации.

Конфигурация отвечает за представление существующих свойств. Новое физическое свойство нужно реализовать в модели, формате и компиляторе, затем добавить привязку `read_property`/`write_property` в `core/editor/properties`. GUI и обработчики полей остаются общими; JSON сам по себе не добавляет физику.

У S/D есть `semiconductor_model` (0=ideal, 1=PWL), `ron`, `roff`; у D также
`forward_voltage`, `charge_model` (0/1), `transit_time`, `carrier_lifetime`, `initial_charge`.
Для PWL эти поля показываются через `when`. Числовые параметры
можно вывести в публичный интерфейс подсхемы. У `samples` кнопка импорта общая
для любого поля с таким редактором; единица значения берётся из его конфигурации.

Изменения применяются одной транзакцией Document. Панель свойств и поле на холсте используют один разбор значений и одинаковые ограничения. Некорректный ввод не меняет модель. Синтаксис JSON, уникальность типов/полей и тип редактора проверяются при загрузке; ошибка внешнего файла показывается при запуске с его именем.

Редактор `number` автоматически заменяет десятичную запятую точкой до вставки текста, сохраняя Undo и положение курсора. Это распространяется на числовые подписи, столбец времени в `events` и оба столбца `samples`; к `text` и многострочным `points` такая обработка не применяется. Ограничения диапазона и SI-единицы проверяет общий разбор свойств.

Для T конфигурация `thyristor.json` задаёт `semiconductor_model`, Ron/Roff/Vf,
`holding_current` (A), `initial_latched` (bool), начальный `closed` и `events`.
Последние два поля скрыты при внешнем gate. Числовой Ih доступен публичным
параметрам подсхем; динамика заряда диода к T не применяется.

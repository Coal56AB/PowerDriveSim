# Архитектурные решения — Milestone 0

## Конвейер и границы
Модель содержит UUID, электрические узлы, ориентированные атомарные ветви,
геометрию, исходные состояния и записанные gate events. Компилятор валидирует
модель, назначает неизвестные в порядке UUID, формирует stamps и разреженный
структурный шаблон. Reference CPU исполняет неизменяемый IR, результаты
хранят каналы и происхождение. GUI и внешний backend не включены в ядро.

Пока граф плоский. Flattening, типизированные signal/gate-порты и публичные
порты составных схем — следующий этап, не подменяются фиктивными классами.
Fast paths отсутствуют; все поддерживаемые схемы идут через generic solver.

## Численные соглашения
Все значения SI, double. Напряжение v = u(positive)-u(negative),
ток ветви положителен от positive к negative. Ground = 0 V.
Для источника тока положительное значение означает отток из positive.
Отрицательная мощность v*i источника означает отдачу энергии.

MNA содержит узловые напряжения и токи V/C/L/S. C и L имеют явные
branch unknowns, чтобы одинаково описывать начальные условия и переключения.
Backward Euler:
- C: v_new - h/C * i_new = v_old
- L: v_new - L/h * i_new = -L/h * i_old
- V: v = source
- S closed: v = 0; S open: i = 0

При t=0 C фиксирует начальное напряжение, L — начальный ток. Решается
алгебраическая согласованность. Несогласованные идеальные ограничения,
например источник непосредственно параллельно C, пока диагностируются
адресной топологической диагностикой; импульсные токи и индекс-редукция DAE не поддержаны.

Каждый шаг заканчивается не позже следующего gate event. До фронта
интегрируется старая топология. На фронте все gates применяются атомарно,
затем алгебраические величины решаются при непрерывных C/L состояниях.
Время фронта записывается один раз, с правосторонними алгебраическими
значениями. Это исключает применение новой топологии к интервалу до фронта.
Сетка привязана к t=0; укороченный шаг не сдвигает последующие точки сетки.

## Trapezoidal — первый блок Milestone 1
- C: v_new - h/(2C)*i_new = v_old + h/(2C)*i_old
- L: v_new - 2L/h*i_new = -2L/h*i_old - v_old

Начальная алгебраическая задача даёт iC(0) и vL(0), поэтому первая точка
не подменяется шагом BE. После gate batch выполняется та же алгебраическая
задача с сохранёнными состояниями; производные обновляются справа от фронта.
Выбранный метод сохраняется в profile и CSV. Без событий метод имеет второй
порядок; на гладкой идеальной LC сохраняет квадратичную энергию.

## Разреженные матрицы
Reference CPU использует разреженные строки std::map и Gaussian elimination
с row scaling и partial pivoting. Нули не требуют плотного хранения.
Порог pivot 1e-14 после масштабирования, проверка scaled residual <= 1e-9.
Это диагностические пороги, не gmin и не изменение схемы.
Структурный шаблон IR — надмножество возможных ненулевых коэффициентов.
Эталон намеренно ещё не оптимизирован: есть allocations и fill-in.

Для Optimized CPU выбран Eigen SparseLU: поддерживает общие разреженные
системы, позволяет отделять анализ структуры от численной факторизации.
Включение зависимости и differential tests — Milestone 4; сейчас ядро
собирается без скачиваний. Собственный эталон остаётся независимой проверкой.
Источник: [Eigen SparseLU](https://eigen.tuxfamily.org/dox/classEigen_1_1SparseLU.html).

## GUI
Целевой toolkit — Qt 6 Widgets, QGraphicsScene/QGraphicsView, с отдельными
документом редактора, историей команд и фоновым worker симуляции.
Graphics View выбран для выборки, трансформаций, сцен и событий элементов.
Аппаратное ускорение viewport проверяется отдельно; GUI не имеет stamps.
Источник: [Qt Graphics View](https://doc.qt.io/qt-6/graphicsview.html).
Локально найден Qt 5.15; он не объявляется целевым GUI и не нужен Milestone 0.
До GUI требуется подобрать и проверить совместимый Qt 6/toolchain.

## GPU abstraction
IR содержит физические операции и разреженный pattern, без CUDA/Vulkan типов.
Будущий backend contract: capability query, compile, execute, cancel,
report с точностью, устройством и причинами fallback. Первый кандидат
для прототипа — Vulkan Compute, затем выбор по реальным differential tests,
float64 capabilities и измерению overhead на целевых платформах.
Это решение о границе и плане прототипа, не заявление о готовом GPU.
Источник: [Vulkan Compute](https://docs.vulkan.org/guide/latest/compute_shaders.html).
Auto и ускорения нельзя объявлять до benchmark на Milestone 4.

## Формат и зависимости
C++20, CMake >=3.20, стандартная библиотека. Формат v3 с миграциями v1/v2 документирован
в [project-format.md](project-format.md). Выбран простой текстовый record
format, чтобы прототип работал офлайн без внешнего JSON parser.
Расширения x- сохраняются дословно; неизвестная основная семантика и
неподдержанная версия отклоняются. При расширении схемы нужна явная миграция.
Случайных процессов нет. Повторяемость гарантируется в одной сборке/профиле;
битовая идентичность разных компиляторов и архитектур не обещается.

## Пределы прототипа
Есть Qt UI, иерархия и Scope. SDK, машины, GPU и Controller ещё не реализованы.
Результаты хранятся в памяти; Stop проверяется между шагами и не прерывает
одну факторизацию. Benchmark печатает оценку payload и измеренный OS peak RSS.
Нет автоматической коррекции схемы. Неизвестные виды компонентов отклоняются.
## Ideal diode — базовая нелинейность Milestone 1

D: positive = anode, negative = cathode. Проводящий диод задаёт v=0,
запертый i=0; решение удовлетворяет i>=0, v<=0 в сохранённых допусках.
Нет Ron/Roff, Vf, recovery и скрытых шунтов. value/initial/closed у D должны
быть нулевыми; state вычисляется, а не задаётся gate event.

Active-set solve начинает с предыдущего принятого набора diode states.
При нарушении complementarity меняет состояния; если trial state сингулярен,
исследует соседние состояния. Это важно, например, для диода, питаемого
источником тока: off trial сингулярен, но on state физически корректен.
Поиск детерминирован по UUID, ограничен max_iterations (1..1024, default 64).
Нет предкомпиляции всех комбинаций. Непринятые trial решения не обновляют C/L.
Нелинейность отключена для графа без диодов; физические уравнения те же.

При исчерпании бюджета: nonlinear_convergence с UUID, временем, числом
попыток и residual V/A. Полная общая сходимость произвольной сети идеальных
диодов не гарантируется; особенно вырожденных loops с неуникальными токами.
Состояния естественной коммутации диодов определяются на концах шагов;
локализация незапланированных zero crossings пока не реализована.
Gate edges по-прежнему обрабатываются точно, с согласованием iL/uC.
Проверки включают оба integration methods, RC charge/hold, bridge обеих
полярностей, current-driven diode и RL freewheel с неизменным iL на фронте.

## Документ и проводники Milestone 1
Document хранит исходный wired graph, snapshots транзакций и 100 undo-операций.
resolve_connections объединяет только явно связанные conserving endpoints.
Directed gate wires разворачивают recorded patterns в атомарные switch events.
Недопустимые соединения не меняют документ. Удаление провода разделяет сеть.
GUI получает готовую net map для подсветки и не формирует электрические уравнения.
Преобразование legacy nets создаёт явные провода с воспроизводимыми UUID;
обратная компиляция сохраняет численный результат исходной RC.
Выбран Qt 6.5.3 для совместимости с имеющимся MSVC 2019:
https://doc.qt.io/qt-6.5/supported-platforms.html

## Реализованный desktop

Qt 6 Widgets и Concurrent подключаются опцией PDS_BUILD_DESKTOP. Qt-зависимости ограничены apps/desktop и UI-тестом. Холст редактирует Document, а worker компилирует и исполняет неизменяемую копию Project. Модель и численный путь общие с CLI. Иерархия разворачивается до атомов с картой исходных UUID и путей экземпляров перед компиляцией.

Сохранение через QSaveFile отделено от текстового writer. Scope читает Result без изменения исходных отсчётов, хранит в Project только представление и выбор каналов. CSV экспортирует все записанные отсчёты выбранных каналов.
